# Проверка проекта Di-SMART — 31.10.2026

## Результат

Автоматические проверки охватили весь проект (около 200 исходных TS/TSX-файлов без сгенерированного Prisma-клиента). Вручную проверены критические пути: подбор вариантов, корзина, пересчёт цены, создание и повтор заявки, уведомления, авторизация и действия админки, загрузчик изображений.

Это проверка кода и перечисленных сценариев, а не гарантия отсутствия любых ошибок на всех устройствах.

## Исправлено

1. **Фото выбранного цвета в корзине.** Раньше обязательная базовая композиция каталога имела приоритет над цветовым снимком. Из-за этого чёрный iPhone 18 Pro мог отображаться бордовым, а MacBook Neo — серебристым. Теперь выбранный цвет имеет приоритет, а при отсутствии цветового фото сохраняется прежняя логика базового изображения. Изменены `src/lib/cart-resolve.ts` и `src/constants/content/catalog-media.ts`; добавлены три регрессионных теста.
2. **Количество в карточке товара.** Кнопка «+» позволяла выбрать больше 20, но корзина принимала максимум 20. Теперь лимит согласован с корзиной; при достижении 20 кнопка отключается. Изменён `src/components/product/ProductInfo.tsx`.
3. **Зависимости.** Next.js обновлён с 16.3.4 до 16.4.3, Sharp — с 0.35.4 до 0.35.5, Prisma и оба адаптера — до 7.10.1. Версия `eslint-config-next` согласована с Next.js; совместимые транзитивные обновления записаны в `package-lock.json`. Основные версии библиотек не менялись, миграции базы не выполнялись.
4. **Браузерные проверки.** Существующий проверочный сценарий оформления учитывает обязательные отметки ознакомления с документами и однозначно выбирает пустую корзину в основном содержимом. Добавлен отдельный сценарий проверки цвета, лимита количества и запрета неавторизованного доступа в админку.

## Остаётся открытым

### Загрузка новых фотографий через админку на Vercel

`src/app/admin/(protected)/products/image-actions.ts` сохраняет файлы через `mkdir` / `writeFile` в `public/uploads/products`. На Vercel локальная файловая система функции не подходит для постоянного хранения загрузок. Нужно подключить объектное хранилище и адаптировать сохранение/удаление изображений, либо использовать сервер с постоянным диском и проверить выдачу загруженных файлов в production-режиме. Имеющиеся фотографии, поставляемые со сборкой, продолжают работать.

Это ограничение обнаружено по коду и документации платформы; реальная попытка загрузить или удалить фото клиента не выполнялась. Хранилище в рамках этой проверки не подключалось.

### Замечания к инструментам разработки

После совместимых обновлений полный аудит npm оставляет 16 записей умеренного уровня в цепочке ESLint / minimatch. Это связанные записи по одной проблеме обработки glob-шаблонов; в `npm audit --omit=dev` замечаний нет. Предложение npm с `--force` предполагает несовместимую замену ESLint, поэтому оно не применялось. Нужна последующая совместимая версия инструментов либо отдельное обновление и проверка их зависимостей.
